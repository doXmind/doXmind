# doXmind 1.11.0 publication checklist

Status: Pending release validation

Change the status to exactly `READY TO PUBLISH` only after every unchecked item
is complete. Publication verifies and exposes the existing immutable draft; it
must never rebuild or replace candidate bytes.

## Build provenance

| Item             | Value                                     |
| ---------------- | ----------------------------------------- |
| App version      | `1.11.0`                                  |
| Source commit    | _record after the candidate build_        |
| Source tree      | _record after the candidate build_        |
| Signed artifacts | _`1.11.0-artifacts.sha256`, once created_ |
| Validation       | _`1.11.0-validation.md`, once written_    |

## Gate

- [x] `package.json` and `package-lock.json` agree on `1.11.0`.
- [x] 1723 unit tests across 129 files, 81 Electron native-boundary tests, and
      266 backend tests pass on the release commit.
- [x] `npm run lint` reports no errors and `npx tsc --noEmit` is clean.
- [x] The frontmatter contract fixture covers the YAML block sequence Obsidian
      writes by default, and the Electron and browser-development stores are
      asserted against the same file.
- [x] The inline-tag grammar is implemented twice — renderer and main process —
      and both are asserted against `tests/fixtures/page-tag-contract.json`.
- [x] Every registered command has a label in both message catalogs, asserted
      against the registry rather than by comparing the catalogs to each other.
- [x] The keyboard reference, the command registry and the native menu are
      asserted to agree, so the shortcuts panel cannot drift from the bindings.
- [x] Snapshots are written only under `DATA_DIR`, are bounded by count, age and
      total bytes, and a snapshot failure is asserted not to fail the Page save.
- [x] Sixteen behaviours were driven on the running Electron app against a seeded
      Obsidian-shaped vault, including the frontmatter round-trip, tab-indent
      outdent, tag counting, search operators, replace-all, snapshot contents,
      the Hotkeys page and the Chinese interface.
- [ ] A new `v1.11.0` draft contains signed and notarized candidate assets built
      from the recorded `doXmind-app` source commit.
- [ ] The committed SHA-256 manifest, GitHub asset digests, stable DMG alias, and
      `latest-mac.yml` version, names, sizes, and SHA-512 values all match.
- [ ] The downloaded DMG and update ZIP pass integrity, Developer ID,
      Gatekeeper, notarization ticket, bundle version, architecture, and
      packaged-runtime boundary checks.
- [ ] Packaged Electron GUI acceptance passes from the downloaded candidate.
- [ ] Page and Attachment recovery checks leave Markdown, source Attachments,
      `.doxmind`, `.bak`, `.lock`, and `.corrupt-*` artifacts byte-identical.
- [ ] A signed, installed update from the current public latest to `1.11.0`
      restarts and cold-launches successfully.
- [ ] Build provenance above records the exact source commit and the verified
      signed artifact names and hashes.
- [ ] The matching website update is ready, and its version label will deploy
      only after the verified release becomes public/latest.
- [ ] The immediate release window is confirmed and the fixed latest-download
      alias plus automatic-update metadata are ready to expose the same bytes.

Every unchecked item above requires the signed candidate to exist and be
verified on a Mac against the downloaded bytes. None of them may be ticked from
the source tree alone.

The ticked items were verified from the source tree and against a development
Electron build. They do not substitute for the candidate verification below
them.
