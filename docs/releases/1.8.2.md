# doXmind 1.8.2 release notes

doXmind 1.8.2 is a focused desktop-resilience hotfix for the blank or frozen
window that could remain after the Electron Renderer failed during startup or
an application update.

## Renderer recovery

- If the Renderer disappears, its main-frame load fails, or the window does not
  reach first paint within 15 seconds, doXmind replaces the failed window once
  and preserves its current file or folder target.
- A recovered window must remain stable before its automatic retry budget is
  restored, preventing a repeated startup crash from creating windows forever.
- If the automatic replacement also fails, a native error dialog offers
  **Retry** or **Quit** instead of leaving an invisible or blank window.

## Safe close and quit

The existing save handshake remains unchanged for a healthy Renderer. When the
Renderer is already gone, however, Close and Quit now finish immediately rather
than waiting forever for a save response that cannot arrive. The same safeguard
applies if the Renderer disappears while a close is already pending.

## Local Markdown boundary

Recovery stays entirely inside the Electron desktop process. It does not weaken
the Renderer sandbox, start a Python/FastAPI service, create a sidecar, or alter
the Markdown source. Pages remain portable `.md` or `.markdown` files, and
Attachments remain ordinary local files.

The packaged GUI suite now verifies the normal local workspace flow plus three
failure paths: no first paint, two consecutive startup failures with native
Retry/Quit handoff, and a force-crashed interactive Renderer with its Markdown
target and Block editing restored.
