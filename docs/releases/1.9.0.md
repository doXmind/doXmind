# doXmind 1.9.0 release notes

doXmind 1.9.0 is a Block-editing release. Every Block's hover, keyboard, and
editing behaviour was measured against Notion and Feishu Doc and brought in line
with whichever of the two reads better, while every Page stays one portable
Markdown file.

## The caret goes where you put it

- Clicking a Block places the caret at the character you clicked, not at the end
  of the Block.
- Up and down arrows leave a Block only from its first or last visible line, so a
  wrapped paragraph lets the caret walk its own lines first, and they keep your
  column when they cross into the next Block.
- Left and right arrows cross the Block boundary; forward Delete joins the next
  Block.
- In a Block containing bold, italic, or code, Enter, Backspace, and the arrow
  keys now act on the text you can see rather than on hidden Markdown
  delimiters.

## Undo and Chinese input

- Undo takes back a word at a time instead of a character at a time. A Markdown
  autoformat, a structural change, moving to another Block, and a pause each
  start a new undo step.
- An IME composition is a single edit, committed once. Candidate text is no
  longer interrupted while you are still choosing characters.
- The insert menu filters on pinyin as you type it, so `/biaoti` finds the
  heading commands. `、` opens the menu as well as `/`.

## Direct manipulation

- The hover controls no longer disappear in the gap above a heading, appear in
  the same frame as the pointer, and sit on the Block's first line of text.
- Dragging shows a translucent copy of the Block you picked up and a single
  insertion line at the nearest boundary, and the Page scrolls when you hold a
  Block near an edge. A drop that would change nothing shows no line.
- Dragging a nested list item to a new place re-indents it so it stays a list
  item.
- Dragging across Blocks selects them. Selecting from the page margin sweeps a
  marquee. With Blocks selected, typing replaces them, and a toolbar offers Turn
  into, Copy, Duplicate, and Delete for the whole selection.

## Blocks in detail

- Code Blocks are syntax highlighted, show no ``` fences, and carry their
  language in a small control.
- Callouts show an icon and colour for their type.
- Table cells can be clicked into directly, Tab moves between them, Tab at the
  end adds a row, and column alignment is honoured.
- Bold, italic, inline code, and strike have keyboard shortcuts, and adding a
  link asks for its destination instead of inserting a placeholder.
- Empty Blocks show what they are, an empty heading keeps its label, and the
  space below the last Block is a click target for a new paragraph.
- Clicking into a Block no longer changes its text size, spacing, or colour.

## Markdown remains the source of truth

- Every operation writes canonical Markdown and preserves untouched source, line
  endings, and unsupported syntax. Two cases that could rewrite a list into raw
  code — pasting a deeply nested list, and dragging a nested item to the top of a
  Page — are fixed.
- Syntax highlighting renders as text, never as markup, so nothing in a Page can
  become live content.
- There is no Page sidecar and no rich-text runtime. Unsupported structures stay
  editable as raw Markdown.
- The release stays fully local in the single Electron desktop runtime. It adds
  no account, cloud service, AI runtime, telemetry, or Attachment editor.
