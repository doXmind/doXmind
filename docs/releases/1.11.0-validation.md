Apple timestamp requests failed intermittently on different resource files;
the final build used an external wrapper that retried only that exact error,
at most five times per invocation, with unchanged codesign arguments. Signing,
secure timestamps, hardened runtime, and notarization remained enabled.

The provenance change updates release documentation and the packaged GUI
harness only. The harness now recognizes `Insert block` and the `Turn into`
submenu, including Escape returning to the parent before closing it. It does
not change any downloaded application bytes.

## Legacy file preservation

The current main branch has removed Page and Attachment recovery commands.
This validation checks their rejection rather than claiming a recovery UI is
present. A dedicated packaged-app fixture opened a CRLF Markdown Page and a
read-only PDF, and invoked the four retired recovery command names; all were
rejected as unhandled shell commands.

All 18 source and legacy files remained byte-identical, with no extra files:
the Markdown and PDF plus hidden and same-name Page/PDF `.doxmind` families,
each including `.bak`, `.lock`, and `.corrupt-fixture` members. The packaged
GUI PDF export/cancellation checks separately preserved Page/legacy bytes and
workspace file inventory.

## Installed upgrade

The signed public 1.10.0 app ran in an isolated user-owned installation
folder. A loopback-only feed served the unchanged downloaded 1.11.0 ZIP.
The operator completed the macOS installation authorization. The updater
reported checking, available, and downloaded events for version 1.11.0.

ShipIt recorded installation completion at 2026-09-05 00:49:30 UTC and
successful LaunchServices relaunch at 00:49:31 UTC. The test's initial
five-second process assertion did not find a separate surviving process;
the normal launch shares the single-instance profile with the existing desktop
app, unlike the isolated test launch. No independent-process restart claim is
based on that assertion.

The installed bundle reports 1.11.0 and retains its deep signature and stapled
notarization ticket. A subsequent cold launch of that installed bundle with
fresh isolated user data passed all 22 packaged GUI checks, with no renderer
page errors or console errors. Thus both the actual signed replacement and
the cold-started updated application were verified, without replacing the
user's `/Applications/doXmind.app`.
