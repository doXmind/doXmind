  `codesign --verify --deep --strict`, `xcrun stapler validate`, and
  Gatekeeper assessment as a Notarized Developer ID application.

## Downloaded-candidate GUI and recovery gate

The packaged Electron acceptance suite launched the App extracted from the
downloaded update ZIP with isolated user data and a temporary workspace. All
23 checks passed with no renderer `pageerror` or `console.error`, including
native menus, source-backed Block editing, Collections, recovery, image
import, renderer recovery, local PDF export, and settings.

The page-recovery and attachment-recovery checks kept Markdown, the source PDF,
and the complete `.doxmind` and `.lock` artifact family byte-identical. The PDF
export and cancellation checks also preserved the Page, legacy artifacts, and
workspace file inventory.

## Squirrel update gate

A clean application directory was populated from the public `v1.8.3` update
ZIP. Its unmodified App passed deep code-signature and stapled-ticket checks.
A loopback-only Squirrel feed served the unchanged Draft `1.10.0` ZIP above;
the signed `1.8.3` App emitted checking, available, and downloaded events for
`1.10.0`, then downloaded that ZIP through its native `autoUpdater`.

`quitAndInstall` handed the payload to ShipIt, which replaced the isolated App
and relaunched it. The replacement reported version `1.10.0`, retained a valid
deep signature and stapled ticket, and then passed the same 23 packaged GUI
checks on a fresh user-data directory. No `/Applications` application or user
workspace was used or modified.

## Publication boundary

Publication must only flip this verified Draft to public/latest. It must not
rebuild or upload assets. Immediately afterward, verify the public latest
release, fixed DMG URL, `1.8.3` update response, and `1.10.0` no-update response
against these same bytes before deploying the matching website version.
