# doXmind 1.8.0 release notes

## What changes in 1.8.0

doXmind now has one editable content type: a Markdown **Page** backed by a real
`.md` or `.markdown` file. PDF, spreadsheet (`.xlsx`, `.xlsm`, `.csv`), and HTML
files remain ordinary local **Attachments**.

- The New menus create only a Page, Folder, or Page from Template. They no longer
  create blank PDFs or workbooks.
- Attachments open in one shared read-only surface with **Open Externally** and
  **Reveal**. They do not open a doXmind PDF or spreadsheet editor.
- Direct Attachment move, rename, delete, and same-name replacement remain
  disabled while legacy recovery evidence is gated. Moving or renaming a parent
  folder keeps its complete subtree together.
- Opening a normal Attachment creates no editor sidecar and never rewrites the
  source file.
- Existing PDF/Excel editor state may be eligible for an explicit, unverified
  recovery attempt. Recovery creates a new comparison copy; it does not update
  the original Attachment.

This release establishes the safe transition state. It does not mark LEGACY-03
complete, and the frozen legacy editor/write code is not yet eligible for
removal until the manual compatibility gate passes.

## Before upgrading

Back up the workspace folder. If an older doXmind build was used to edit a PDF
or workbook, preserve the complete evidence set together:

- the original `.pdf`, `.xlsx`, `.xlsm`, or `.csv` source;
- the main hidden `.doxmind` sidecar;
- every matching `.bak` file;
- every matching `.lock` file; and
- every matching `.corrupt-*` forensic copy.

Do not rename, combine, replace, or clean up these files before recovery. A
successful export is not a signal to delete them.

## Legacy PDF and workbook recovery

The 1.8.0 recovery bridge inspects only the main sidecar and `.bak` candidates.
It does not read `.lock` or `.corrupt-*`; those files remain untouched evidence.
When the main and backup contain different recoverable states, the app asks
which candidate to try.

Every recovery attempt:

1. hashes the exact source bytes used for the attempt;
2. treats the historical cache hash only as a mismatch guard, not proof of
   editor provenance;
3. refuses partial or unsupported application;
4. downloads a new `<name> recovered.pdf` or `<name> recovered.xlsx`; and
5. leaves the source and complete evidence set unchanged.

Compare the recovered copy with the original before using it.

### Known recovery limits

- A missing or mismatched source hash blocks the attempt.
- Unsupported PDF edits, page rotations, or text that would require silent
  resizing fail as a whole.
- Spreadsheet recovery refuses state it cannot account for, including saved
  `filters`, `filterMode`, unsupported structural operations, and UI-only state.
- CSV recovery produces `.xlsx`.
- `.xlsm` recovery produces `.xlsx`; VBA macros are not included.
- Attachments do not currently have an embedded editor or document preview. Use
  **Open Externally** for ordinary reading and editing.

## Manual compatibility fallback

Do not choose an older build by guesswork. The exact fallback below was verified
only for schema-v2 PDF and workbook sidecars created and reopened by 1.7.8. It
does not establish compatibility with earlier sidecar shapes, corrupt evidence,
source mismatches, or every `.bak`/`.corrupt-*` state. If the evidence falls
outside that scope—or its origin is unknown—stop after preserving it.

| Item              | Verified value                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- |
| Validation status | **Conditionally verified for 1.7.8-created schema v2 only**                                                           |
| Exact version     | doXmind `1.7.8`, macOS arm64                                                                                          |
| Download URL      | [Official 1.7.8 ZIP](https://github.com/doXmind/releases/releases/download/v1.7.8/doXmind-1.7.8-arm64-mac.zip)        |
| SHA-256           | `08aff3948166824089b1a9b5b6964868af442372e3ae240360c3aa78f9c5b9e3`                                                    |
| Test platform     | macOS 26.5 (25F71), Apple M4 Max, arm64                                                                               |
| Validation record | [PDF/XLSX fallback record](https://github.com/doXmind/doXmind-app/blob/main/docs/releases/1.8.0-legacy-validation.md) |

The fallback preserved both source Attachments, but 1.7.8 rewrote sidecar
metadata while opening and exporting and created a `.doxmind/index.json` file.
It must therefore run only against a complete duplicate:

1. Quit every doXmind process.
2. Duplicate the Attachment's containing folder into a separate recovery
   location and confirm the complete evidence set is present.
3. Download only the exact artifact above and verify its SHA-256.
4. Extract and run it from a temporary location, then open only the isolated
   copy—never the original workspace.
5. Export to a new file, compare the result with the original Attachment, and
   keep the untouched evidence set until the result is independently verified.

For the complete workflow, see the
[User Guide](https://github.com/doXmind/doXmind-app/blob/main/docs/USER_GUIDE.md).
For the active product boundary and LEGACY-03 status, see
[Product Direction](https://github.com/doXmind/doXmind-app/blob/main/docs/PRODUCT_DIRECTION.md).
