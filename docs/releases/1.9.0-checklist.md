# doXmind 1.9.0 publication checklist

Status: Pending release validation

Change the status to exactly `READY TO PUBLISH` only after every unchecked item
is complete. Publication verifies and exposes the existing immutable draft; it
must never rebuild or replace candidate bytes.

## Gate

- [x] `package.json` and `package-lock.json` agree on `1.9.0`.
- [x] Caret continuity, undo granularity, IME atomicity, Block selection, drag
      and drop, links, and per-kind Block detail have direct regressions: 936
      unit tests across 88 files.
- [x] Chromium GUI acceptance covers the source-backed Block workflow, including
      the hover gutter, multi-Block selection, and hierarchy-safe structural
      operations.
- [x] Two source-corrupting paths are fixed with regressions that pin the bytes:
      pasting a nested list keeping its depth, and a dragged nested list item
      re-indenting instead of becoming an indented code block.
- [x] Syntax highlighting renders document-derived content as text, never as
      markup, keeping the untrusted-input boundary in ADR-0011.
- [x] Public notes preserve the Electron-only, Markdown-only Page and read-only
      Attachment boundary.
- [ ] A new `v1.9.0` draft contains exactly six signed and notarized candidate
      assets built from the recorded `doXmind-app` source commit.
- [ ] The committed SHA-256 manifest, GitHub asset digests, stable DMG alias, and
      `latest-mac.yml` version, names, sizes, and SHA-512 values all match.
- [ ] The downloaded DMG and update ZIP pass integrity, Developer ID,
      Gatekeeper, notarization ticket, bundle version, architecture, and
      packaged-runtime boundary checks.
- [ ] Packaged Electron GUI acceptance passes from the downloaded candidate with
      all 23 checks, including Block interaction, recovery, and local PDF export.
- [ ] Page and Attachment recovery checks leave Markdown, source Attachments,
      `.doxmind`, `.bak`, `.lock`, and `.corrupt-*` artifacts byte-identical.
- [ ] A signed, installed `1.8.3` to `1.9.0` Squirrel/ShipIt update restarts and
      cold-launches successfully.
- [ ] Build provenance above records the exact source commit and six verified
      signed artifact names and hashes.
- [ ] The matching website update is ready, and its version label will deploy
      only after the verified release becomes public/latest.
- [ ] The immediate release window is confirmed and the fixed latest-download
      alias plus automatic-update metadata are ready to expose the same bytes.

Every unchecked item above requires the signed candidate to exist and be
verified on a Mac against the downloaded bytes. None of them may be ticked from
the source tree alone.

Do not publish or modify the superseded `v1.8.0` draft.
