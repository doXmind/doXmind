## Packaged-app smoke

The exact downloaded update ZIP was quarantined, extracted, and run from an
isolated temporary location with separate `DATA_DIR` and Electron user-data
directories. It did not replace the existing app in `/Applications`.

The run proved:

- every New menu offered only Page, Folder, or Page from Template;
- a Page could be created, edited, saved to Markdown plus its Page sidecar,
  closed, relaunched, and reopened from disk;
- PDF, XLSX, XLSM, CSV, and HTML opened in the shared read-only Attachment
  surface without editor or save controls;
- PDF **Open Externally** launched Preview and HTML **Reveal** selected the
  source in Finder;
- ordinary Attachment bytes remained unchanged and opening them created no
  Attachment sidecars; and
- an externally added and then renamed Markdown Page appeared through the
  native workspace watcher without a manual refresh.

This is useful candidate evidence but is not the complete packaged-app release
gate. A clean Finder drag-install and smoke run on a separate macOS test account
is still required. The external-edit-on-window-focus check also remains a
manual follow-up because the current-account run did not produce a conclusive
observation.

## Legacy recovery matrix

Each case used an isolated workspace and download directory. Before and after
the attempt, the source plus matching main sidecar, every `.bak`, `.lock`, and
`.corrupt-*` member were compared by directory membership, SHA-256, inode, and
mtime. The disposable `.doxmind/index.json` workspace index was excluded from
the recovery evidence set, as documented by the product storage contract.

| Case                      | Fixture scope                                                                                     | Result                                                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| PDF main-only             | Archived 1.7.8 PDF source and sidecar                                                             | Exported a six-page copy containing `LEGACY-PDF-178-EVIDENCE`; evidence unchanged.                                                       |
| PDF backup-only           | The same archived PDF sidecar placed only at `.bak`                                               | Exported the same six-page marker; evidence unchanged.                                                                                   |
| PDF differing main/backup | Archived main plus a derived backup whose equal-length marker is `LEGACY-PDF-BAK-EVIDENCE`        | The UI required an explicit candidate choice; choosing backup exported the backup marker; evidence unchanged.                            |
| XLSX backup-only          | Derived behavior fixture: archived workbook editor state plus a matching `parsedCache.sourceHash` | Exported a three-sheet XLSX with `LEGACY-178-EVIDENCE` and all 11 formulas; the formula-error scan found no matches; evidence unchanged. |
| XLSX unknown              | Unmodified archived main and backup without `parsedCache.sourceHash`                              | Displayed preservation guidance, offered no recovery action, and created no output; evidence unchanged.                                  |
| PDF source mismatch       | Derived sidecar with a nonmatching source hash                                                    | Refused the attempt with mismatch guidance, created no output, and left evidence unchanged.                                              |

The recovered workbook was also inspected and rendered with artifact-tool
spreadsheet validation. The derived XLSX fixture proves current bridge behavior
only; it is not historical provenance for a recoverable workbook sidecar.

LEGACY-03 remains **Pending**. No archived historical XLSX sidecar with a valid,
matching source hash is available, and pre-1.7.8 top-level
`{pdf_editor, excel_editor, ...}` sidecars have not passed this packaged-app
manual procedure. Frozen legacy editors and write paths therefore remain
ineligible for removal.
