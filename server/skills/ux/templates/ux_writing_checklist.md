# UX Writing Checklist

## Pre-Writing Questions

### Context
- [ ] What is the user trying to accomplish?
- [ ] What screen/flow is this copy for?
- [ ] What action came before this?
- [ ] What action comes after?
- [ ] What emotional state might the user be in?

### Requirements
- [ ] Character/word limits known
- [ ] Technical constraints understood
- [ ] Voice and tone guidelines reviewed
- [ ] Related copy patterns checked

---

## Clarity Checklist

### Plain Language
- [ ] No jargon or technical terms (unless necessary)
- [ ] Short sentences (under 20 words)
- [ ] Active voice preferred
- [ ] Common words over fancy ones
- [ ] Acronyms spelled out first time

### Specificity
- [ ] Tells user exactly what will happen
- [ ] No vague words ("stuff," "things," "various")
- [ ] Specific actions, not general ones
- [ ] Numbers instead of "some" or "many"

### Scannability
- [ ] Front-loaded key information
- [ ] One idea per sentence
- [ ] Bullet points for lists
- [ ] Bold for emphasis (sparingly)

---

## User-Centered Checklist

### Focus
- [ ] Written from user's perspective
- [ ] Addresses user's goal, not company's feature
- [ ] Uses "you" not "we" (mostly)
- [ ] Avoids internal terms

### Helpfulness
- [ ] Guides user to success
- [ ] Anticipates questions
- [ ] Provides necessary context
- [ ] Offers next steps

### Emotional Awareness
- [ ] Tone matches user's likely emotional state
- [ ] Empathetic when things go wrong
- [ ] Celebratory when things go right
- [ ] Calm during stressful moments

---

## Action Checklist

### Buttons
- [ ] Starts with a verb
- [ ] Describes the specific action
- [ ] 1-4 words
- [ ] Matches user's intent (not your goal)

### CTAs
- [ ] Clear what happens when clicked
- [ ] Primary and secondary are visually distinct
- [ ] Destructive actions clearly labeled

### Links
- [ ] Describes destination (not "click here")
- [ ] Indicates if opens new window (when needed)
- [ ] No broken or outdated links

---

## Form Checklist

### Labels
- [ ] Clear and concise
- [ ] Uses familiar terms
- [ ] Required fields marked
- [ ] Associated with correct field

### Placeholder Text
- [ ] Shows expected format
- [ ] Not used as label (disappears)
- [ ] Provides helpful example

### Help Text
- [ ] Explains requirements upfront
- [ ] Prevents errors before they happen
- [ ] Positioned near relevant field

### Validation
- [ ] Error appears near the problem
- [ ] Explains what went wrong
- [ ] Shows how to fix it
- [ ] Inline when possible

---

## Error Message Checklist

### Content
- [ ] Explains what happened
- [ ] Tells why (if helpful)
- [ ] Shows how to fix it
- [ ] Offers alternative if applicable

### Tone
- [ ] Doesn't blame the user
- [ ] Apologetic when it's our fault
- [ ] Calm and helpful
- [ ] Avoids alarming language

### Technical
- [ ] No error codes without explanation
- [ ] No technical jargon
- [ ] Specific, not generic

---

## Empty State Checklist

### Content
- [ ] Explains what this area shows
- [ ] Tells why it's empty (if not obvious)
- [ ] Guides user to populate it

### Design Support
- [ ] Clear CTA button
- [ ] Appropriate illustration/icon
- [ ] Not depressing or accusatory

---

## Notification Checklist

### Content
- [ ] Most important info first
- [ ] Brief (scan in 3 seconds)
- [ ] Clear action (if needed)

### Type
- [ ] Correct severity (info/success/warning/error)
- [ ] Can be dismissed when appropriate
- [ ] Doesn't block critical tasks

---

## Consistency Checklist

### Terminology
- [ ] Same term for same thing throughout
- [ ] Matches glossary/terminology guide
- [ ] Consistent capitalization

### Voice
- [ ] Matches product voice guidelines
- [ ] Consistent with other screens/flows
- [ ] Doesn't introduce new personality

### Patterns
- [ ] Follows established UI patterns
- [ ] Error messages follow same format
- [ ] Button labels consistent with similar actions

---

## Accessibility Checklist

### Screen Readers
- [ ] Alt text for meaningful images
- [ ] Descriptive link text
- [ ] Form labels properly associated
- [ ] Error messages announced

### Cognitive
- [ ] Simple language
- [ ] Clear hierarchy
- [ ] No time pressure (unless necessary)
- [ ] Instructions don't rely on color alone

### Inclusive Language
- [ ] Gender-neutral
- [ ] No ableist language
- [ ] Culturally considerate
- [ ] No idioms that don't translate

---

## Localization Checklist

### Translation-Ready
- [ ] No concatenated strings
- [ ] Allows for text expansion (30-50%)
- [ ] No text in images
- [ ] Complete sentences

### Cultural
- [ ] No idioms or cultural references
- [ ] Date/time format flexible
- [ ] Units/measurements adaptable
- [ ] Color meanings considered

---

## Final Review

- [ ] Read aloud (does it sound natural?)
- [ ] Checked against real data/scenarios
- [ ] Reviewed in actual UI context
- [ ] Tested with representative users
- [ ] Spelling and grammar checked
- [ ] Approved by stakeholders
